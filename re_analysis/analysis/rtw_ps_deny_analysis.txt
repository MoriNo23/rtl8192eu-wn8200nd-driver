Function: rtw_ps_deny

**Function Purpose:**  
This function implements a reference-counted power-save veto mechanism. It sets a bit in `pwrpriv->ps_deny` (protected by a spinlock) to prevent the runtime power-save subsystem from idling the adapter while a specific subsystem (scan, EAPOL, LPS, etc.) needs the radio awake. The bitmask allows multiple concurrent “deny” reasons; the device only enters power-save when the mask returns to zero.

**Windows vs Linux Differences:**  
Fundamental architectural mismatch.  
- **Linux** uses a driver-internal bitmask (`ps_deny`) + runtime PM callbacks (`runtime_idle`/`runtime_suspend`).  
- **Windows NDIS** exposes power management through `NdisMIdleNotificationConfirm/Complete` and Dx-state transitions (D0↔D3). The Windows driver maintains *NDIS power references* (`NdisSetSystemPowerState`, `NdisMIdleNotification`) rather than a private bitmask. There is no 1:1 equivalent of `rtw_ps_deny` in the Windows binary; the same logical “keep awake” is expressed by holding an NDIS idle-reference or delaying the idle confirmation.

**Backport Candidate:** **no**

**Reason:**  
The function is a Linux-kernel idiom (bitmask + spinlock) that maps to *completely different* NDIS primitives on Windows. The Windows binary contains no analogous routine to copy—only the NDIS idle-notification imports prove the opposite approach is used. Backporting would mean re-implementing NDIS power-reference counting inside Linux, which is architecturally wrong and unnecessary.

**Expected Impact:**  
None. The current Linux implementation is already the correct, idiomatic way to gate runtime PM in a Linux driver.
